# UX 2차 개선 설계 (2026-07-30)

브레인스토밍으로 확정한 설계. 사용자 선택: 원문 후처리 = **A(정돈 렌더링)**, 준비 점검 표 = **A(단일 표)**.

## 1. 인용 각주 클릭 → 원문 스크롤·하이라이트 (완료)

`feat/cite-jump`로 구현 완료, `feat/ux-round2`에 머지됨. 섹션 제목 앵커
(`findSectionLine`) 기반 — 목차 매치는 건너뛰고 본문 매치 우선, 미발견 시 하이라이트 생략.

## 2. 원문 정돈 렌더링

hwp 추출 마크다운의 프론트 후처리 후 마크다운 렌더:

- hwp 페이지참조 깨진 문자(`銨ȃ` 류 — 라틴 확장·PUA 문자가 낀 목차 페이지 참조) 제거
- 전 셀이 빈 표 행, 구분선만 남은 기형 표 정리
- hwp 제목표(`| N |  | 제목 |` + 구분선)를 섹션 제목으로 변환
- 정리된 마크다운을 기존 `Markdown` 컴포넌트(GFM 표)로 렌더 — 표가 진짜 표로 보임
- 인용 하이라이트는 렌더된 DOM에서 섹션 제목을 찾아 스크롤·플래시하는 방식으로 이식.
  기능 저하 금지: 각주 클릭 → 해당 섹션으로 이동이 계속 동작해야 한다
- RFP 원문을 코드·테스트에 하드코딩하지 않는다 (NDA)

## 3. 준비 점검·적격 확인 표 (단일 표)

요건 | 판정 | 근거 3열 표 + 판정 색 배지(✓충족·✕미충족·?미확인)를 공용 컴포넌트로:

- 채팅 `report` 카드 (`cards.tsx`)
- 문서 뷰어 참가자격 판정 블록 (`doc-viewer.tsx` QualificationBlock)
- 파일로 저장되는 본문(`chat-flows.tsx` buildReport)도 마크다운 표로

판정 재서술 금지 원칙 유지 — 백엔드 verdict·사유를 그대로 표기.

## 4. 생각 과정(reasoning 요약) 표시

- 백엔드(GPTPilots_Project): 생성 LLM 호출을 OpenAI Responses API로 전환,
  reasoning summary 수신 → `/ask` 응답에 `reasoning` 필드(옵션) 추가.
  원본 CoT는 OpenAI가 미제공 — 요약이 상한.
- 프론트: 답변 위 접이식 "생각 과정" 블록. 필드 없으면 렌더 안 함(하위호환).

## 5. 채팅 패널 경계 드래그 리사이즈

채팅 패널 왼쪽 경계 드래그 핸들. 최소~최대 폭 제한, 너비 localStorage 저장.

## 6. 공고 클릭 시 새 채팅 생성 버그 제거

공고를 열 때 채팅 세션이 새로 만들어지는 동작 제거 — 기존 대화 유지.
원인 추적 후 세션 생성 트리거를 문서 열기에서 분리한다.
